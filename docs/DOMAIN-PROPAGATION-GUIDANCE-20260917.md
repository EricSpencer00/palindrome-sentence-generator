## What the current code actually does

`experiments/assumption_core_scene_solver_20260916.py` enumerates complete slot
products with `itertools.product`, then checks complete strings. Its
`minimal_core` returns the first failed Boolean check. This is not a conflict
explanation over lexical assignments and cannot eliminate a subtree before
rendering it. Its two palindrome checks also use the same reversal expression.

`experiments/semantic_slot_lattice_smt.py` similarly selects every slot and
renders both complete clauses before checking palindrome equality. Despite its
name, it does not invoke an SMT backend or propagate domains on partial states.
These observations concern those two files, not every solver in the repository.

## Bounded feasibility result

A read-only experiment imported `SCENES` from the assumption-core solver and
computed the product size and first/last character domains. There was no new
candidate sweep and no vocabulary change.

| Scene | Complete assignments | First characters | Last characters | Intersection |
| --- | ---: | --- | --- | --- |
| courier_past | 139,968 | a, t | e, n, r | empty |
| garden_present | 139,968 | a, t | s | empty |

Every nonempty letter palindrome must have equal first and last characters.
Consequently, **all 279,936 complete assignments are impossible at the root**.
This is a finite-domain proof for these scenes, not an impossibility claim about
English. Two endpoint-domain checks suffice; scoring 240 complete candidates
cannot improve this result. No intact candidate was generated by this diagnostic.

Reproduction:

```python
import importlib.util
import math

spec = importlib.util.spec_from_file_location(
    "solver", "experiments/assumption_core_scene_solver_20260916.py")
solver = importlib.util.module_from_spec(spec)
spec.loader.exec_module(solver)
for scene in solver.SCENES:
    domains = scene["slots"]
    first = {word[0] for word in domains[0]}
    last = {word[-1] for word in domains[-1]}
    print(scene["id"], math.prod(map(len, domains)), first, last, first & last)
```

## One concrete next repair

Implement a work queue that propagates **word domains and character-position
domains** before branching. For a bounded total letter length, keep each slot's
possible start offsets, possible word lengths, and lexical alternatives. A word
alternative survives only if at least one supported offset gives every emitted
letter a compatible mirrored-position letter. Recompute reachable offsets when
a domain shrinks; iterate to a fixed point. Branch on the smallest remaining
supported domain. Record the responsible slot assignments when a domain empties
and reuse that nogood only within the same length and structural assumptions.
Variable-length and optional slots require offset support; treating their
positions as fixed would prune valid solutions.

First implement the endpoint case above and require the exact 279,936-assignment
root rejection with zero complete renderings. Then test propagation against
exhaustive enumeration on tiny artificial domains, including variable lengths;
both must produce identical exact solution sets. Only after that test passes
extend the same propagator to ordinary independently authored prose domains.
Do not merely add a different noun bank to these impossible frames.

Use the 38-letter sentence only as a withheld benchmark. Search fresh lengths
above 38 with optional grammatical constituents so the solver can represent
longer sentences without copying or wrapping that seed. This removes a search
inefficiency; it does not establish that the supplied language has any long
readable palindrome. Empty propagated domains should produce an explicit finite
failure proof, not a nonexact prose example advertised as progress.

For any eventual survivor, independently normalize and scan from both ends,
retain the complete rendered prose and lexical-choice trace, audit local
catalogue/repetition/mirror exclusions, and separately assess ordinary English
readability. A hash records provenance; it is not an independent readability
or construction check. The next decision is whether a verified propagator
finds any nonempty endpoint-compatible prose domain, not whether another
complete candidate receives a better score.
