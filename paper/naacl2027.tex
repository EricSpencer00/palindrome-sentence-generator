\begin{abstract}
We measured whether a larger search-resource bundle changes exact letter-level palindrome coverage, and audited automatic language diagnostics on outputs that passed mechanical checks. Across 20 fresh seeds, three length bands, two search implementations, and two resource bundles (240 runs), basic-valid coverage rose from 0/120 to 66/120. The paired increase was 0.55 (95\% seed-cluster bootstrap interval: 0.35--0.75); both implementations returned 33/60 outputs under the larger bundle. Beam width, candidate limit, branching, and time budget changed together, so the estimate is for the bundle and does not identify which setting accounts for the increase. Brown gain exceeded the same-word shuffle baseline for 40/66 outputs; GPT-2 likelihood did so for 37/66; DeepSeek V3.2 tied all 66 comparisons. We collected no human ratings. The evidence supports a resource-sensitive coverage result, not a claim that generated outputs are readable.
\end{abstract}

\section{Introduction}

An exact letter-level palindrome has a normalized ASCII-letter tape equal to its reversal. This property is easy to verify and says nothing about whether the text forms ordinary prose. Prior work searches corpus n-gram graphs or uses residual-character search to construct palindromes \citep{papadopoulos2015palindromes,norvig2002palindrome}. Here we study a narrower question: when a fixed search task yields no eligible output, does a larger resource bundle change exact-output coverage, and what do automatic language diagnostics say about outputs that are found?

The v4 study is an adaptive follow-up to an earlier 180-run comparison with no basic-valid outputs. It compares two operational implementations and scores selected outputs against deterministic same-word shuffles using a document-held-out Brown bigram model, a pinned GPT-2 checkpoint, and one blinded DeepSeek V3.2 judgment per output. Neither implementation reproduces the cited systems; these model diagnostics are not human evaluations.

\section{Experiment}

\paragraph{Tasks and search.} Each task uses one of three target bands (30--49, 50--79, or 80--119 normalized letters). Both algorithms begin from an empty text and share a frozen vocabulary, state constraints, and basic structural gate: supported ASCII rendering, exact palindrome tape, length band, lexicon-backed words, ordinary short words, and exclusions for known catalogue items and templates. The outside-in arm closes when its residual character debt is a palindrome; center-out closes only on empty overhang. The short-word predicate accepts words longer than two letters or a frozen allowlist of 32 one- and two-letter forms. A search returns its eligible closure with the largest accumulated Zipf frequency score per normalized letter. Repeated words are retained and reported. Outputs are lower-case space-joined words, with an initial capital and final period.

The previous v3 comparison had 90 tasks per algorithm and yielded no basic-valid outputs. After toy-vocabulary controls confirmed that both search implementations could reach a known target, we froze v4 on 20 fresh seeds (4000--4019) crossed with the three bands. Each of the 60 seed-by-band blocks ran both algorithms under both resource bundles, for 240 runs. The original bundle used beam/candidate/per-parent limits of 60/200/8 and a 45-second cooperative budget; the escalated bundle used 256/800/32 and 180 seconds. Both have a 400-step ceiling. These settings change together, so the comparison does not isolate any one resource. No run reached its deadline.

The vocabulary is derived from the project's frozen 30K word list, then filtered through its English lexicon and ordinary-short-word list. Search priorities use English Zipf frequencies from \code{wordfreq} 3.1.1, add 0.3 per word character, subtract 2 for each prior word use and 4 for an adjacent repeated word, then select the eligible closure with the highest accumulated score per letter \citep{speer-2022-wordfreq}. This is a search heuristic, not a calibrated measure of sentence quality.

The primary outcome is the fraction of requested runs returning an output that passes the shared basic gate. We compute the paired escalated-minus-original difference and a percentile bootstrap interval over 20 whole seed clusters (20,000 resamples; PRNG seed 20260925). Runs with no output stay in the denominator. The follow-up is adaptive: its design responds to v3's null yield, so it is not an independent confirmation of a pre-v3 hypothesis.

\paragraph{Language diagnostics.} We scored only the 66 selected v4 outputs; no v3 output existed to score. For each output we generated 32 deterministic permutations of the same tokens, preserving sentence token counts. Brown order gain is the add-0.1 word-bigram mean log probability minus the shuffle mean. The model trains on 401 Brown documents; the other 99 are excluded from training, not used as a validation set \citep{kucera-francis-1967,loper-bird-2002-nltk}. GPT-2 uses the pinned \url{openai-community/gpt2} revision \url{607a30d783dfa663caf39e06633721c8d4cfcd7e}; its value is candidate mean causal token log probability minus the mean for the same 32 shuffles \citep{radford2019language,huggingfacegpt2}. DeepSeek V3.2 received one counterbalanced, blinded candidate--shuffle pair per output through Bedrock (temperature 0, top-p 1, maximum 256 tokens) \citep{awsbedrockdeepseekv32}. Prompts, visible responses, hashes, and token usage are archived. AWS did not provide a model seed, so an API rerun need not reproduce the exact response.

\section{Results}

\paragraph{Coverage.} The original bundle returned 0/120 basic-valid outputs; the escalated bundle returned 66/120 (0.550). The paired difference was 0.550, with a 95\% seed-cluster bootstrap interval of [0.350, 0.750]. Each algorithm returned 33/60 under the escalated bundle. Median time per task was 0.014 seconds in the original bundle and 8.954 seconds in the escalated bundle; no task timed out. Four resource settings changed together, so the comparison estimates the bundled change and cannot identify which setting accounts for the coverage increase. The full task-level counts, including closure candidates and failures, are in the artifact.

The 66 outputs contain 52 distinct strings across the two arms (26 per arm); 54 pass the additional mechanical anti-shortcut checks. Those extra checks require distinct content words and reject whole-word reversals, repeated multiword units, proper palindromic subspans, and listed catalogue templates. Still, 36/66 contain the exact phrase ``one poem association.'' Thus exactness, lexicon membership, and these construction screens leave conspicuous repetitive language. Brown and GPT-2 scores are conditional on search success and are not direct measures of meaning. DeepSeek tied all 66 pairs; in 38 responses its feature note was ``Both are word salad with no coherent meaning.'' This is one model's judgment, not a human rating.

\section{Discussion and limitations}

The supported finding is that the escalated resource bundle recovered basic-valid outputs on 66 of 120 tasks where the original bundle recovered none. The algorithms tied in coverage. This does not show that one growth direction is better, that runtime alone caused the increase, or that the returned texts are readable. In the success-conditioned sample, the 54/66 strict-pass figure is a mechanical sensitivity check, not an estimate of strict search coverage. The repeated phrase in 36 outputs makes the difference between exactness and useful language concrete.

This is an adaptive experiment on one vocabulary, three narrow length bands, and 20 fresh seeds. v4's settings bundle beam width, candidate limit, branching, and time budget; the two methods also use different native closure rules. The language diagnostics are post-selection automatic scores for v4 successes only. Brown measures local word-order fit under one corpus model, GPT-2 measures likelihood under one pinned model, and DeepSeek is a single unseeded API judgment per item. None replaces blind human ratings of grammaticality and coherence \citep{howcroft-etal-2020-twenty,khashabi-etal-2022-genie}. A separate 11-text audit in the repository is retrospective and is not a second experiment. We make no population, human-readability, causal, or general system-superiority claim.

\section*{Reproducibility and assistance}

The checksum-manifested archive \url{v4-reproducibility.zip} contains frozen manifests, row-level outputs, scorer inputs and responses, source code, model revisions, and rerun commands. Brown and GPT-2 scores can be recomputed from the saved inputs; DeepSeek's stored response can be re-parsed, but provider rerun stability was not measured. The reported Bedrock charge is an estimated USD 0.0098 from recorded tokens and published rates \citep{awsbedrockpricing}. Generative AI assisted code, drafting, and internal review; no AI review is human evaluation. No participant data were collected.
